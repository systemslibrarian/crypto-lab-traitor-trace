NEW DEMO BRIEF
- Repo name:         crypto-lab-traitor-trace
- Short name (H1):   Traitor Trace
- Subtitle:          Broadcast encryption · subset-cover revocation · traitor tracing
- One-liner:         One ciphertext readable by any authorized subscriber and no one else, a revoked member locked out without rekeying anyone, and a leaked decoder traced back to whoever built it.
- Concept to teach:  Encrypting to a group is easy if you encrypt N times. Broadcast encryption asks the harder question: one ciphertext, any authorized subset, revocation without touching everyone else's keys — and when a pirate decoder appears, the ability to point at which subscriber's keys are inside it. The keys are the fingerprint.
- Primitives/spec:   Subset-Difference method (Naor-Naor-Lotspiech 2001), complete subtree method, key derivation over a binary tree of subscribers, traitor tracing via subset testing, collusion resistance bounds, AES-256-GCM for the payload
- Accent (--accent): #0369A1
- Favicon emoji:     📡
- In scope:
    * Real crypto throughout: HKDF-derived tree keys, real AES-256-GCM session encryption, real subset-cover computation. A 16-subscriber binary tree, fully inspectable.
    * The naive baseline first — establish the cost. Encrypt once per recipient: 16 subscribers, 16 ciphertexts, and adding one subscriber costs one more. Show the header size growing linearly. Then revoke one and watch every remaining key need reissue. This makes the rest matter.
    * THE SUBSET COVER — the headline mechanism. The learner clicks subscribers to revoke, and the algorithm computes the covering set live:
        16 subscribers, revoke #7 and #12
              → cover = {subtrees excluding 7 and 12}
              → header = 4 encrypted session keys, not 14
      Animate the tree: revoked leaves go dark, the cover subtrees light up, the header shrinks. Every non-revoked subscriber derives the session key from exactly one subset key they already hold. Nobody is rekeyed. Show a revoked subscriber's decoder failing against the real GCM.
    * THE TRACING — the payoff. A pirate decoder appears (the learner builds it from one or more subscribers' key sets). Feed it crafted ciphertexts that only some subsets can decrypt. Binary-search the tree by watching what the decoder can and cannot open. Narrow it to the traitor. The learner runs the search and names the leaker.
    * Collusion panel — the honest limit: two traitors pool their keys. Show tracing still working. Then push past the scheme's collusion bound and show it failing to isolate a single traitor. State the bound precisely; do not imply tracing is unconditional.
    * The library framing — this is the one that's native to you: a licensed database, per-institution keys, a campus whose subscription lapses (revoke without touching 200 other institutions), and a credential that shows up on a proxy site. Same math, your actual job. One panel, stated plainly, no editorializing about vendors.
    * Real-world panel: AACS on Blu-ray used subset-difference and NNL tracing — and what happened when device keys leaked anyway. Accurate, no overclaim.
- Non-goals:         Not a group-messaging lab (link mls-group — MLS gives forward secrecy via TreeKEM; this gives stateless revocation with no member interaction; one line on the difference). Not a key-management lab (link envelope-kms). Not an attribute-based encryption lab (name ABE, don't build it). No watermarking/fingerprinting of the CONTENT — this traces keys, not media. No DRM polemic.
